## **职员 \| employee**



> 当前设计将职员基础信息与人事资料合并为一张表。实际数据库设计时需根据规范化要求合理拆分为职员基础信息表和人事资料扩展表。
> 
> 



### **字段一览**



|序号|字段中文名|字段名|数据类型|必填|说明|
|---|---|---|---|---|---|
|1|职员 ID|`employee_id`|BIGINT|是|主键，自增|
|2|姓名|`name`|VARCHAR\(100\)|是|职员姓名|
|3|姓名（日文）|`name_jp`|VARCHAR\(100\)|否|日文姓名|
|4|职员状态|`status`|VARCHAR\(20\)|是|ACTIVE（在职）/ RESIGNED（离职，终态）/ SUSPENDED（停职）|
|5|入职日期|`hire_date`|DATE|否|入职日期|
|6|所属部门|`department`|VARCHAR\(100\)|否|所属部门名称|
|7|职位|`position`|VARCHAR\(100\)|否|职位名称|
|8|雇佣类型|`employment_type`|VARCHAR\(50\)|否|雇佣类型，如正社員/契約社員/パート等|
|9|薪酬类型 ID|`salary_type_id`|BIGINT|否|关联薪酬类型表|
|10|基本工资|`base_salary`|DECIMAL\(12,2\)|否|基本給金额|
|11|时薪|`hourly_wage`|DECIMAL\(10,2\)|否|時給金额（仅时薪制职员）|
|12|银行名称|`bank_name`|VARCHAR\(100\)|否|工资转账银行|
|13|分行名称|`bank_branch_name`|VARCHAR\(100\)|否|银行分行名称|
|14|账户类型|`bank_account_type`|VARCHAR\(20\)|否|普通/当座等|
|15|账户号码|`bank_account_number`|VARCHAR\(20\)|否|银行账户号码|
|16|创建时间|`created_at`|TIMESTAMP|是|记录创建时间|
|17|更新时间|`updated_at`|TIMESTAMP|是|记录更新时间|



**职员 ID \| employee\_id**

职员唯一标识，主键。自增整数类型。



**姓名 \| name**

职员姓名，必填字段。



**姓名（日文） \| name\_jp**

职员的日文姓名，用于年末调整申告书、源泉徴収票等日本法定文书。



**职员状态 \| status**

职员在职状态：ACTIVE（在职）、RESIGNED（离职，终态）、SUSPENDED（停职）。仅 ACTIVE 状态的职员允许参与考勤打卡、请假申请、薪酬计算、年末调整申告等业务流程。状态变更为 RESIGNED 或 SUSPENDED 时，系统自动终止其考勤打卡和薪酬计算权限。



**入职日期 \| hire\_date**

职员入职日期，用于计算在职年数及年末调整対象判定（全年在籍）。



**所属部门 \| department**

职员所属部门，由管理员在人事资料管理中设置。



**职位 \| position**

职员职位名称。



**雇佣类型 \| employment\_type**

雇佣类型描述，如正社員、契約社員、パート等。



**薪酬类型 ID \| salary\_type\_id**

关联至 `salary_type` 表。决定职员的薪酬计算方式（固定工资/时薪工资/特别工资）。



**基本工资 \| base\_salary**

基本給金额。DECIMAL 正数类型存储。



**时薪 \| hourly\_wage**

時給金额。仅时薪制职员填写。



**银行名称 \| bank\_name**

工资转账用银行名称。



**分行名称 \| bank\_branch\_name**

工资转账用银行分行名称。



**账户类型 \| bank\_account\_type**

银行账户类型，如普通預金、当座預金等。



**账户号码 \| bank\_account\_number**

工资转账用银行账户号码。



**创建时间 \| created\_at**

记录创建时的系统时间戳。



**更新时间 \| updated\_at**

记录最近更新时的系统时间戳。

> 当前设计将系统账户与权限信息合并为一张表。实际数据库设计时需根据规范化要求合理拆分为系统账户表和账户权限关联表。

## **考勤配置 \| attendance\_config**



### **字段一览**



|序号|字段中文名|字段名|数据类型|必填|说明|
|---|---|---|---|---|---|
|1|配置 ID|`config_id`|BIGINT|是|主键，自增|
|2|月度考勤结算日期|`settlement_day`|INT|是|每月第几日进行考勤统计结算，如 25|
|3|IP 白名单|`ip_whitelist`|JSON|否|允许打卡的 IP 地址列表|
|4|GPS 地理位置限制|`gps_location`|JSON|否|允许打卡的地理位置范围|
|5|细碎时间规则|`fragmented_time_rules`|JSON|是|迟到/早退/加班舍入规则|
|6|生效起始日期|`effective_from`|DATE|是|配置生效起始日期|
|7|生效结束日期|`effective_to`|DATE|否|配置生效结束日期，为空则表示长期有效|
|8|创建时间|`created_at`|TIMESTAMP|是|记录创建时间|
|9|更新时间|`updated_at`|TIMESTAMP|是|记录更新时间|



**配置 ID \| config\_id**

主键，自增整数。



**月度考勤结算日期 \| settlement\_day**

每月进行考勤统计结算的日期（如每月 25 日）。该日期需在薪酬配置中早于薪酬结算日。



**IP 白名单 \| ip\_whitelist**

允许打卡的 IP 地址列表。以 JSON 数组格式存储。为空时表示不限制 IP。



**GPS 地理位置限制 \| gps\_location**

允许打卡的地理位置范围。以 JSON 格式存储（如中心点经纬度 \+ 半径）。为空时表示不限制 GPS。



**细碎时间规则 \| fragmented\_time\_rules**

迟到、早退、加班各场景的舍入规则。以 JSON 格式存储，包含场景类型和对应的舍入值（如 5 分钟/15 分钟/30 分钟/自定义值）。



**生效起始日期 \| effective\_from**

配置项生效的起始日期。对尚未开始的考勤期间生效。



**生效结束日期 \| effective\_to**

配置项生效的结束日期。为空表示长期有效。



**创建时间 \| created\_at**

记录创建时的系统时间戳。



**更新时间 \| updated\_at**

记录最近更新时的系统时间戳。

## **考勤打卡记录 \| attendance\_punch**



### **字段一览**



|序号|字段中文名|字段名|数据类型|必填|说明|
|---|---|---|---|---|---|
|1|打卡 ID|`punch_id`|BIGINT|是|主键，自增|
|2|职员 ID|`employee_id`|BIGINT|是|关联职员表|
|3|打卡日期|`punch_date`|DATE|是|打卡发生的自然日期|
|4|打卡开始时间|`start_time`|TIME|是|基于打卡日期的相对时间，区间 `[00:00:00, 24:00:00)`|
|5|打卡结束时间|`end_time`|TIME|是|基于打卡日期的相对时间，须大于 start\_time|
|6|休息开始时间|`break_start_time`|TIME|是|基于打卡日期的相对时间，须在 \[start\_time, end\_time\] 区间内|
|7|休息结束时间|`break_end_time`|TIME|是|基于打卡日期的相对时间，须在 \[start\_time, end\_time\] 区间内|
|8|状态|`status`|VARCHAR\(20\)|是|NORMAL（正常）/ PENDING（待修正）/ CORRECTED（已修正）/ REJECTED（已驳回）|
|9|IP 地址|`ip_address`|VARCHAR\(45\)|否|打卡时的 IP 地址|
|10|GPS 位置|`gps_location`|JSON|否|打卡时的 GPS 地理位置|
|11|创建时间|`created_at`|TIMESTAMP|是|记录创建时间|
|12|更新时间|`updated_at`|TIMESTAMP|是|记录更新时间|



**打卡 ID \| punch\_id**

主键，自增整数。



**职员 ID \| employee\_id**

关联至 `employee` 表。



**打卡日期 \| punch\_date**

打卡发生的自然日期。同一日期内允许多次打卡，但打卡时间不可重叠。



**打卡开始时间 \| start\_time**

基于打卡日期的相对时间。例如 00:00:00 代表打卡日期 00:00:00，24:00:00 代表打卡日期次日 00:00:00。区间 `[00:00:00, 24:00:00)`。



**打卡结束时间 \| end\_time**

基于打卡日期的相对时间，须大于 start\_time。



**休息开始时间 \| break\_start\_time**

休息时段的开始时间，须在 \[start\_time, end\_time\] 区间内。



**休息结束时间 \| break\_end\_time**

休息时段的结束时间，须在 \[start\_time, end\_time\] 区间内。



**状态 \| status**

打卡记录状态：NORMAL（正常）、PENDING（待修正，职员已提出修改申请）、CORRECTED（已修正，终态，修改申请已通过）、REJECTED（已驳回，终态，修改申请被驳回）。



**IP 地址 \| ip\_address**

打卡时记录的职员 IP 地址，用于可选的 IP 白名单校验。



**GPS 位置 \| gps\_location**

打卡时记录的职员 GPS 地理位置，以 JSON 格式存储经纬度，用于可选的 GPS 限制校验。



**创建时间 \| created\_at**

记录创建时的系统时间戳。



**更新时间 \| updated\_at**

记录最近更新时的系统时间戳。
